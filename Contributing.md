# Contributing Guide

Thank you for contributing to this project. This guide explains the standard process for making changes, creating branches, submitting pull requests, and participating in code reviews.

## 1. Getting Started

Before making changes, contributors should:

* Clone or fork the repository.
* Read the README.md to understand the project.
* Set up the required frontend and backend environments.
* Make sure the project runs correctly before starting development.

## 2. Repository Structure

The project is organized into the following main folders:

* `frontend/` – Contains the frontend application.
* `backend/` – Contains the backend application and services.
* `docs/` – Contains project documentation and supporting documents.
* `README.md` – Provides an overview and setup information for the project.

## 3. Creating an Issue

Before starting new work:

* Check whether an existing GitHub Issue already covers the requirement.
* If the requirement is new, create a GitHub Issue.
* Clearly describe the problem, requirement, or proposed improvement.
* Use appropriate labels and assign the issue to the responsible contributor.

## 4. Creating a Branch

Contributors should not make changes directly on the main branch.

Create a separate branch for each issue or task.

Recommended branch format:

`feature/issue-<issue-number>-<short-description>`

Example:

`feature/issue-4-contributor-guidelines`

Keep each branch focused on its assigned issue.
